# Layer 3: Data Pipeline

![Data Pipeline Architecture](images/data_pipeline.png)

*รูปที่ 3.1: ข้อมูลจาก Mosquitto ผ่าน Telegraf ออกสองทางพร้อมกัน*

payload ก้อนเดียวเข้า Mosquitto ในเครื่อง แล้ว Telegraf ดึงไปกระจายเข้า InfluxDB กับ Kafka
จุดที่แตกสองทางอยู่ที่ Telegraf ไม่ใช่ที่ Kafka ถ้าสาย ML ล่ม กราฟสถานะจริงยังขึ้นปกติ

## Telegraf

อ่านทางเดียวเขียนออกสองปลายทาง ค่าที่ตั้งไว้และเหตุผล

| ค่า | ทำอะไร | ถ้าไม่ตั้ง |
| :--- | :--- | :--- |
| `name_override` | ตั้งชื่อ measurement เป็น `traffic_6620301002` | กลายเป็น `mqtt_consumer` ชนกับของทั้งห้อง |
| `tag_keys` | เก็บ `camera_id`, `student_id` | parser ทิ้ง string ทั้งคู่ แยกไม่ออกว่าของใคร |
| `json_time_key` | ใช้เวลาที่กล้องตรวจจับ | ใช้เวลาที่ Telegraf รับ ข้อมูลเลื่อน |
| `omit_hostname` | ไม่ติด tag host | host คือ container ID ที่เปลี่ยนทุกครั้ง กราฟขาดเป็นท่อน |
| `json_transformation` | แปลง payload ขาออก Kafka ให้แบนราบ | ได้ `{"fields":{...},"tags":{...}}` คนละรูปแบบกับ MQTT |

## InfluxDB

`172.16.2.117:8086` org `my-org` bucket `mini_project` ซึ่งใช้ร่วมกันทั้งห้อง
ทุก query ต้องกรอง `student_id` เสมอ

| measurement | tags | fields |
| :--- | :--- | :--- |
| `traffic_6620301002` | `camera_id`, `student_id`, `topic` | `car`, `motorcycle`, `bus`, `truck`, `vehicles_in_roi`, `slow_vehicle_ratio`, `congestion_level` |
| `traffic_prediction_6620301002` | `camera_id`, `student_id` | `forecast_congestion_level`, `forecast_level_rounded`, `horizon_minutes`, `model_version`, `prediction_for` |

field ทุกตัวเก็บเป็น float เพราะ parser json ของ Telegraf แปลงตัวเลขเป็น float ทั้งหมด

```flux
from(bucket: "mini_project")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r._measurement == "traffic_6620301002")
  |> filter(fn: (r) => r.student_id == "6620301002")
  |> filter(fn: (r) => r._field == "congestion_level")
  |> aggregateWindow(every: 30s, fn: mean, createEmpty: false)
```

## จังหวะเวลา

ทั้งท่อมีตัวกำหนดจังหวะตัวเดียวคือตัวตรวจจับที่ส่งทุก 10 วินาที ทอดที่เหลือได้รับเมื่อไหร่ส่งต่อเมื่อนั้น

`interval = "10s"` ใน `telegraf.conf` ไม่ได้แปลว่าไปดึงข้อมูลทุก 10 วินาที เพราะ `mqtt_consumer`
เป็น service input คือนั่งรอรับอย่างเดียว ตัวที่เป็น 10 วินาทีจริงคือ `flush_interval`
ซึ่งเป็นรอบเทข้อมูลออก ข้อมูลจึงอาจถึงช้ากว่าเวลาใน timestamp ได้ถึง 10 วินาที
