# ML & Logic (Layer 2)

มีโมเดลสองตัว YOLO + ByteTrack ดูสภาพปัจจุบัน และ RandomForest ทายอีก 5 นาที

## โมเดลตรวจจับ

| รายการ | ค่า |
| :--- | :--- |
| โมเดล | `yolo26s.pt` (เปลี่ยนได้ด้วย `--model`) |
| Tracker | ByteTrack |
| ชนิดที่จับ | car, motorcycle, bus, truck |
| Confidence | 0.30 |
| ขนาดภาพเข้าโมเดล | 960 px |

ที่ต้องมี tracker เพราะการตรวจจับอย่างเดียวรู้แค่จำนวนรถ ซึ่งบอกไม่ได้ว่าติดหรือไม่
ต้องมี ID ประจำรถถึงจะเทียบตำแหน่งข้ามเฟรมแล้ววัดความเร็วได้

ตัวกรองสัญญาณรบกวน

- กล่องที่ใหญ่เกิน 25% ของเฟรมถูกตัดทิ้ง
- ชนิดรถใช้การโหวตสะสมทั้ง track ไม่ใช่ผลเฟรมล่าสุด
- track ที่หายเกิน 0.25 วินาทีถูกลืมทิ้ง

## ขอบเขตถนนและสูตรตัดสิน

![ROI Mapping on Video Frame](images/roi_mapping.png)

*ภาพที่ 4 พื้นที่ ROI ที่วาดด้วยเส้นแดงใน `mapreal.png` ระบบนับเฉพาะรถในกรอบนี้*

ขอบเขตถนนวาดเป็นเส้นแดงบนภาพ `mapreal.png` โปรแกรมหาพิกเซลแดงแล้วเติมทึบเป็น mask
แก้ขอบเขตได้ด้วยการวาดรูปใหม่ ไม่ต้องแก้โค้ด

จุดตัดสินว่ารถอยู่ในขอบเขตไหมคือกึ่งกลางขอบล่างของกล่อง (ตรงล้อ) เพราะกล้องกดลงมา
ถ้าใช้จุดกึ่งกลางกล่อง รถนอกถนนที่ตัวสูงจะล้ำเข้ามา

**ขั้นที่ 1** วัดความเร็วรถแต่ละคัน หน่วยเป็นความยาวตัวรถต่อวินาที

$$v_{lps} = \frac{\sqrt{(x_t - x_{t-1})^2 + (y_t - y_{t-1})^2}}{h_{box} \times \Delta t}$$

หารด้วยความสูงกล่องเพื่อตัดผลของระยะใกล้ไกล รถไกลขยับน้อยพิกเซลแต่ตัวก็เล็กตาม
พอหารด้วยขนาดตัวเองแล้วใช้เกณฑ์เดียวกันได้ทั้งจอ แล้วกรองด้วย EMA ให้ค่านิ่ง

**ขั้นที่ 2** นับว่าในหน้าต่าง 5 วินาทีล่าสุดมีตัวอย่างที่ช้ากว่า 0.30 กี่เปอร์เซ็นต์ ได้เป็น `slow_vehicle_ratio`

**ขั้นที่ 3** แปลงเป็นระดับ

| สัดส่วนรถช้า | ระดับ | ความหมาย |
| :--- | :--- | :--- |
| ต่ำกว่า 20% | 0 | รถโล่ง |
| 20 – 34% | 1 | รถไหลๆ |
| 35 – 54% | 2 | รถหนาแน่น |
| 55% ขึ้นไป | 3 | รถติด |

ถ้ามีรถไม่ถึง 4 คัน ระดับถูกบังคับเป็น 0 เพราะสัดส่วนที่คิดจากรถคันสองคันไม่มีความหมาย
และค่านี้ไม่เป็น null เด็ดขาด ไม่งั้นข้อมูลจะขาดช่วงทั้งบนกราฟและตอนเทรน

## โมเดลพยากรณ์ 5 นาที

| รายการ | ค่า |
| :--- | :--- |
| อัลกอริทึม | RandomForestRegressor 300 ต้น |
| ชนิดงาน | regression ค่าต่อเนื่อง 0.0-3.0 |
| จำนวน feature | 20 ตัว |
| Label | `congestion_level` จริงที่เวลา +5 นาที |

feature คือค่าดิบ 7 ตัวจาก payload บวกค่าสถิติย้อนหลัง (ค่าเฉลี่ย 1 และ 5 นาที ค่าสูงสุด
และผลต่างใน 5 นาที ของจำนวนรถและสัดส่วนรถช้า) บวกเวลาอีก 4 ตัว

เวลาแปลงเป็น sin/cos เพราะถ้าใส่ชั่วโมงเป็นเลข 0-23 ตรง ๆ โมเดลจะเห็น 23 กับ 0 ห่างกันสุดขั้ว
ทั้งที่จริงห่างกันชั่วโมงเดียว

สูตรสร้าง feature อยู่ใน `ml_features.py` ที่เดียว ทั้งตอนเทรนและตอนทำนายสดเรียกฟังก์ชันเดียวกัน
ถ้าแยกเขียนสองที่แล้วเพี้ยนจากกัน โมเดลจะเห็นข้อมูลคนละแบบกับตอนเทรน

### ความแม่น

วัดจากข้อมูลจริง ค่าจริง 345 จุด ค่าพยากรณ์ 305 จุด

| วิธีวัด | MAE |
| :--- | :--- |
| โมเดลของเรา | 0.428 |
| เดาว่าอีก 5 นาทีเท่ากับตอนนี้ | 0.730 |
| เดาค่าเฉลี่ยตลอด | 0.962 |

ชนะทั้งสองเส้นฐาน แปลว่าโมเดลเรียนรูปแบบการเปลี่ยนแปลงได้จริง ไม่ได้ลอกค่าปัจจุบันไปวาง
แต่ตัวเลขนี้มาจากคลิปเดียวประมาณหนึ่งชั่วโมง

ห้ามเอาข้อมูลจากคลิปที่เปิดวนซ้ำมาเทรน เพราะจะสอนให้โมเดลเชื่อว่ารถติดเป็นรอบตามความยาวคลิป
