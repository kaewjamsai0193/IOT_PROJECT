# สรุปและข้อเสนอแนะ

## สรุปผลโครงงาน

ระบบเชื่อมการตรวจจับด้วย AI เข้ากับระบบ IoT และการวิเคราะห์ข้อมูลแบบสตรีมได้ครบวงจร
ตั้งแต่อ่านภาพจากกล้อง ตรวจจับและติดตามรถเพื่อวัดความเร็ว สรุปเป็นระดับความติดขัด
ส่งผ่าน MQTT เข้า Telegraf แล้วกระจายเข้า InfluxDB กับ Kafka พร้อมกัน

จุดที่ต่างจากการนับรถทั่วไปคือระบบตัดสินรถติดจากสัดส่วนรถที่เคลื่อนที่ช้า ไม่ใช่จำนวนรถ
และมีโมเดล Machine Learning พยากรณ์ล่วงหน้า 5 นาที ซึ่งวัดแล้วแม่นกว่าการเดาว่า
อีก 5 นาทีจะเท่ากับตอนนี้ ผู้ใช้จึงเห็นทั้งสถานะปัจจุบันและแนวโน้มข้างหน้าในหน้าจอเดียว

## ประโยชน์ที่ได้รับ

- เข้าใจการสร้างระบบ IoT ตั้งแต่ Edge AI จนถึง Dashboard
- เข้าใจการใช้ MQTT และ Kafka สำหรับข้อมูลแบบสตรีม และการใช้ Telegraf กระจายข้อมูลหลายปลายทาง
- เข้าใจ Time Series Database การออกแบบ measurement tag field และการเขียน Flux Query
- ได้ฝึกทำ time-series forecasting ตั้งแต่สร้าง feature จนถึงวัดผลเทียบกับเส้นฐาน
- ได้ฝึกไล่ปัญหาข้ามหลายบริการ โดยดักฟังข้อมูลทีละจุดเพื่อหาว่าข้อมูลหายตรงไหน

## ข้อจำกัด

- ใช้กล้องตัวเดียวและมุมเดียว ถ้าเปลี่ยนมุมกล้องต้องวาดขอบเขตถนนใหม่
- ข้อมูลที่ใช้ทดสอบมาจากคลิปบันทึก ไม่ใช่กล้องสด ความแม่นของโมเดลจึงวัดจากข้อมูล
  ประมาณหนึ่งชั่วโมง ถ้าจะใช้งานจริงต้องเก็บข้อมูลจากกล้องสดหลายวัน
- เกณฑ์ตัดสินความเร็ว 0.30 ความยาวตัวรถต่อวินาที และเกณฑ์ระดับความติดขัด
  เป็นค่าที่ตั้งจากการสังเกตคลิปทดสอบ ควรปรับตามพื้นที่จริง
- ยังไม่ได้ตั้ง alert rule บน Grafana การเตือนจึงเห็นได้เฉพาะบนหน้าต่างของตัวตรวจจับ
- ระบบพึ่งบริการบน Server ถ้า Kafka หรือ InfluxDB หยุดทำงาน ข้อมูลปลายทางจะขาดช่วง

## ข้อเสนอแนะ

- ต่อกล้องสดและเก็บข้อมูลต่อเนื่องหลายวัน เพื่อให้โมเดลเรียนรูปแบบตามชั่วโมงและวันในสัปดาห์ได้จริง
- ตั้ง alert rule บน Grafana ที่ค่าพยากรณ์ เพื่อเตือนก่อนรถติดจริง
- รองรับหลายกล้องโดยแยกด้วย tag `camera_id` ซึ่งโครงสร้างข้อมูลปัจจุบันรองรับอยู่แล้ว
