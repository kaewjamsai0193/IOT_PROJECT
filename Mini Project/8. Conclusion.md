# สรุปและข้อเสนอแนะ

## สรุปผลโครงงาน

ระบบเชื่อมการตรวจจับด้วย AI เข้ากับระบบ IoT และการวิเคราะห์ข้อมูลแบบสตรีมได้ครบวงจร
ตั้งแต่อ่านภาพจากกล้อง วัดความเร็วรถ สรุปเป็นระดับความติดขัด ส่งผ่าน MQTT เข้า Telegraf
แล้วกระจายเข้า InfluxDB กับ Kafka พร้อมกัน

จุดที่ต่างจากการนับรถทั่วไปคือตัดสินรถติดจากสัดส่วนรถที่เคลื่อนที่ช้า ไม่ใช่จำนวนรถ
และมีโมเดลพยากรณ์ล่วงหน้า 5 นาทีซึ่งวัดแล้วแม่นกว่าการเดาว่าอีก 5 นาทีจะเท่ากับตอนนี้

## ประโยชน์ที่ได้รับ

- เข้าใจการสร้างระบบ IoT ตั้งแต่ Edge AI จนถึง Dashboard
- เข้าใจการใช้ MQTT กับ Kafka สำหรับข้อมูลแบบสตรีม และการเขียน Flux Query บน Time Series Database
- ได้ฝึกทำ time-series forecasting ตั้งแต่สร้าง feature จนถึงวัดผลเทียบกับเส้นฐาน

## ข้อจำกัดและข้อเสนอแนะ

- ข้อมูลที่ใช้ทดสอบมาจากคลิปบันทึก ไม่ใช่กล้องสด ถ้าจะใช้งานจริงต้องเก็บข้อมูลหลายวัน
  เพื่อให้โมเดลเรียนรูปแบบตามชั่วโมงและวันในสัปดาห์ได้
- เกณฑ์ความเร็วและเกณฑ์ระดับความติดขัดตั้งจากการสังเกตคลิปทดสอบ ควรปรับตามพื้นที่จริง
- ยังไม่ได้ตั้ง alert rule บน Grafana ควรเพิ่มการเตือนที่ค่าพยากรณ์เพื่อเตือนก่อนรถติดจริง
