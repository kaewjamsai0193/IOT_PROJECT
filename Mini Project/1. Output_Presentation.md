# Layer 1: Output & Presentation

## สิ่งที่ผู้ใช้ต้องการ

คนที่ใช้ระบบนี้อยากรู้สองอย่าง คือตอนนี้ถนนติดหรือโล่ง กับอีก 5 นาทีจะเป็นยังไง
เพราะถ้ารู้ตอนที่ติดแล้วก็สายเกินจะเลี่ยง ต้องรู้ล่วงหน้าถึงจะเปลี่ยนเส้นทางทัน

อีกอย่างที่ต้องรู้คือข้อมูลที่เห็นสดหรือค้าง เพราะระบบจะมีข้อมูลก็ต่อเมื่อตัวตรวจจับทำงานอยู่
ถ้าท่อตายแล้วหน้าจอยังโชว์เลขเดิม คนดูจะนึกว่าถนนโล่งทั้งที่ระบบแค่หยุดส่ง

## หน้าจอ Grafana

![Grafana Dashboard Overview](images/grafana_dashboard.png)

*รูปที่ 1.1: หน้าจอจริงของระบบ ตอนนั้นสภาพปัจจุบันเป็นรถโล่ง ส่วนอีก 5 นาทีโมเดลทายว่ารถไหลๆ*

มี 6 panel

1. **เวลา ณ ปัจจุบัน** บอกเวลาของข้อมูลล่าสุด ไว้ดูว่าข้อมูลสดหรือค้าง
2. **สภาพการจราจรปัจจุบัน** ค่า `congestion_level` ล่าสุด
3. **สภาพการจราจรในอีก 5 นาที** ค่า `forecast_congestion_level` ล่าสุด
4. **จำนวนรถแต่ละประเภท** แยก car, motorcycle, bus, truck
5. **จำนวนรถทั้งหมด** ค่า `vehicles_in_roi`
6. **เทียบค่าจริงกับค่าพยากรณ์** กราฟเส้นย้อนหลัง ไว้ดูว่าโมเดลทายแม่นแค่ไหน

### การ map สี

ใช้ชุดสีเดียวกันทุก panel ที่แสดงระดับ จะได้ไม่ต้องเดาว่าสีนี้ของ panel ไหนแปลว่าอะไร

| ช่วงค่า | ข้อความ | สี |
| :--- | :--- | :--- |
| 0 – 0.5 | รถโล่ง | เขียว `#73BF69` |
| 0.5 – 1.5 | รถไหลๆ | เหลือง `#EAB839` |
| 1.5 – 2.5 | รถหนาแน่น | ส้ม `#FFB357` |
| 2.5 – 3 | รถติด | แดง `#E24D42` |

ต้องตั้งเป็น Range mapping ไม่ใช่ Value mapping เพราะค่าพยากรณ์เป็นทศนิยมอย่าง 1.53
ซึ่งไม่ตรงกับเลขจำนวนเต็มตัวไหนเลย ถ้าใช้ Value mapping panel พยากรณ์จะไม่ติดสี

สี่สีนี้สงวนไว้ให้ระดับความติดขัดเท่านั้น panel จำนวนรถใช้สีอื่น เพราะรถเยอะไม่ได้แปลว่ารถติด
ลองวัดจากข้อมูลจริง 896 จุดแล้ว ถ้าไล่สีตามจำนวนรถจะตรงกับระดับจริงได้มากสุด 73% ที่เหลือขัดกันเอง

### กราฟเทียบความแม่น

ค่าพยากรณ์ถูกเขียนลงฐานข้อมูลที่เวลาต้นทาง ไม่ใช่เวลาที่ทำนายถึง ถ้าเอามาวาดตรง ๆ
เส้นพยากรณ์จะไปทับช่วงเดียวกับเส้นค่าจริง ซึ่งไม่ใช่การเทียบความแม่น ต้องเลื่อนไปข้างหน้า 5 นาทีก่อน

```flux
import "date"

from(bucket: "mini_project")
  |> range(
    start: date.sub(d: 5m, from: v.timeRangeStart),
    stop: date.sub(d: 5m, from: v.timeRangeStop)
  )
  |> filter(fn: (r) => r._measurement == "traffic_prediction_6620301002")
  |> filter(fn: (r) => r.student_id == "6620301002")
  |> filter(fn: (r) => r._field == "forecast_congestion_level")
  |> group(columns: ["camera_id", "_field"])
  |> aggregateWindow(every: 30s, fn: mean, createEmpty: false)
  |> timeShift(duration: 5m)
  |> yield(name: "forecast")
```

เส้นค่าจริงต้องใช้ `aggregateWindow` ชุดเดียวกัน ไม่งั้นจะกลายเป็นเอาค่าเฉลี่ย 30 วินาที
ไปเทียบกับจุดดิบ 10 วินาที

## การแจ้งเตือน

![Alert Notification Example](images/alert_notification.png)

*รูปที่ 1.2: ตอนระบบขึ้นสถานะ JAM จะตีกรอบแดงรอบภาพ มุมซ้ายบนบอกว่ารถช้า 76% และมีรถในพื้นที่ 17.3 คัน*

ตัวตรวจจับจะเตือนเมื่อรถช้าเกิน 55% ในหน้าต่าง 5 วินาทีล่าสุด และต้องมีรถอย่างน้อย 4 คัน
เวลาจะเลิกเตือนต้องลดลงต่ำกว่า 45% ที่ทำแบบนี้เพราะถ้าใช้เส้นเดียวกันทั้งเปิดและปิด
สถานะจะกระพริบไปมาตอนค่าแกว่งอยู่รอบ ๆ เส้น

ระบบไม่มี payload แจ้งเตือนแยกต่างหาก สถานะนี้ไปกับ payload ปกติในรูป `congestion_level = 3`
ปลายทางทุกตัวเลยเห็นเหตุการณ์เดียวกันโดยไม่ต้องมีท่ออีกเส้น

ฝั่ง Grafana ไม่ได้ตั้ง alert rule ไว้ การเตือนของระบบนี้อยู่ที่ตัวตรวจจับที่เดียว
คนดูแดชบอร์ดอ่านสถานะจากสีของ panel เอา
