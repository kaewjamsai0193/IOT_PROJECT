# ปัญหาที่พบและแนวทางแก้ไข

| ปัญหา | สาเหตุ | แนวทางแก้ไข |
| :--- | :--- | :--- |
| ส่งข้อมูลเข้า Kafka ของวิชาโดยตรงไม่ได้ | broker ประกาศ `advertised.listeners` เป็น `localhost:9092` เครื่องอื่นจึงเข้าไม่ถึง | ช่วงแรกอ้อมด้วยการส่ง MQTT ไป VerneMQ แล้วให้ Kafka Connect ดึงเข้า เมื่อแก้เป็น IP จริงแล้วจึงส่งตรง |
| กราฟใน Grafana ขาดเป็นท่อน | Telegraf ติด tag `host` ซึ่งใน container คือ container ID ที่เปลี่ยนทุกครั้ง InfluxDB จึงมองเป็นคนละ series | ตั้ง `omit_hostname = true` |
| `camera_id` และ `student_id` หายไปจากฐานข้อมูล | parser json ของ Telegraf ทิ้งค่า string ทุกตัวที่ไม่ได้ระบุ | ระบุใน `tag_keys` |
| measurement ชื่อ `mqtt_consumer` ชนกับของทั้งห้อง | ไม่ได้ตั้งชื่อ จึงใช้ค่า default | ตั้ง `name_override = "traffic_6620301002"` |
| payload ใน Kafka คนละรูปแบบกับ MQTT | Telegraf ห่อข้อมูลเป็น `{"fields":{...},"tags":{...}}` | ใช้ `json_transformation` แปลงกลับให้แบนราบ |
| ข้อมูลหายเงียบตอน Mosquitto ไม่ทำงาน | `publish()` ไม่โยน exception แต่คืน rc = 4 | เช็ก `info.rc` ทุกครั้งแล้วพิมพ์คำเตือน |
| ความเร็วพุ่งผิดตอนเล่นคลิปวนซ้ำ | ภาพกระโดดกลับต้นคลิป ระบบคิดว่ารถวิ่งข้ามจอในเฟรมเดียว | ล้าง track ทั้งหมดทุกครั้งที่วนกลับต้นคลิป |
| สถานะเตือนกระพริบไปมา | ใช้เส้นแบ่งค่าเดียวกันทั้งตอนเปิดและปิดการเตือน | ใส่ hysteresis เริ่มเตือนที่ 55% เลิกเตือนที่ 45% |
| panel ค่าพยากรณ์ไม่ติดสี | ค่าพยากรณ์เป็นทศนิยม เช่น 1.53 ซึ่ง Value mapping จับไม่ตรง | เปลี่ยนไปใช้ Range mapping |
| สีของ panel จำนวนรถขัดกับ panel ระดับ | ไล่สีตามจำนวนรถ แต่ระดับตัดสินจากความเร็ว | สงวนสีไฟจราจรไว้ให้ระดับเท่านั้น panel จำนวนรถใช้สีอื่น |
| กราฟเทียบความแม่นอ่านผิด | ค่าพยากรณ์ถูกเขียนที่เวลาต้นทาง ไม่ใช่เวลาที่ทำนายถึง | เลื่อนเส้นพยากรณ์ด้วย `timeShift(duration: 5m)` |
| ข้อมูลถี่กว่า 10 วินาที | รันด้วย `--no-show` ซึ่งไม่มีการหน่วงให้เล่นตามเวลาจริง | รันแบบเปิดหน้าต่างเมื่อต้องการข้อมูลไปเทรนโมเดล |
| ปิดโปรแกรมแล้วได้ payload รถเป็น 0 ปนเข้าฐานข้อมูล | ส่งสรุปก้อนสุดท้ายทั้งที่ตัวนับเพิ่งถูกรีเซ็ต | ส่งเฉพาะตอนที่ยังมีเฟรมค้างที่ยังไม่ได้สรุป |
