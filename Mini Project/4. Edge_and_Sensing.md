## เครื่องที่ใช้ประมวลผล

รันบน MacBook ผ่าน PyTorch MPS โค้ดเลือก device เอง ถ้ามี CUDA ใช้ CUDA ไม่มีก็ MPS ไม่มีอีกก็ CPU
ย้ายไปรันบน Jetson หรือ PC ที่มีการ์ดจอได้โดยไม่ต้องแก้โค้ด

ข้ามเฟรมเว้นหนึ่ง (`STRIDE = 2`) ประมวลผลจริงราว 13 fps จาก 27 fps รถไม่ได้เปลี่ยนตำแหน่งมาก
ใน 1/27 วินาที ความเร็วที่วัดจึงไม่เพี้ยนแต่ภาระเครื่องลดครึ่งหนึ่ง

ตอนอ่านจากไฟล์และเปิดหน้าต่าง โปรแกรมหน่วงให้เล่นความเร็วปกติ ข้อมูลจึงห่างกัน 10 วินาทีจริง
ถ้าใส่ `--no-show` จะไม่หน่วง ข้อมูลถี่กว่า 10 วินาที ซึ่งไม่เหมาะจะเอาไปเทรน

## การส่งข้อมูลออก

| รายการ | ค่า |
| :--- | :--- |
| Endpoint | `mqtt://127.0.0.1:1883` |
| Topic | `traffic/6620301002` |
| QoS | 1 |
| ความถี่ | ทุก 10 วินาที |

```python
info = mqtt_client.publish(MQTT_TOPIC, payload_str, qos=1)
if info.rc != mqtt.MQTT_ERR_SUCCESS:
    print(f"ส่ง MQTT ไม่สำเร็จ {MQTT_TOPIC} (rc={info.rc})", file=sys.stderr)
```

ต้องเช็ก `info.rc` ทุกครั้งเพราะ `publish()` ไม่โยน exception ตอนต่อ broker ไม่ได้
มันคืน rc = 4 เงียบ ๆ ข้อมูลจะหายโดยไม่มีคำเตือน

ตอนปิดโปรแกรมจะส่ง payload ก้อนสุดท้ายเฉพาะเมื่อยังมีเฟรมค้างที่ยังไม่ได้สรุป
ไม่งั้นจะได้ payload ที่รถเป็น 0 ปนเข้าฐานข้อมูลทุกครั้งที่ปิด
