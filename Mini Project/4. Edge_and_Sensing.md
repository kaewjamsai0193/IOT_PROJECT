*ภาพที่ 6 ภาพดิบจากกล้องก่อนประมวลผล เป็นมุมสูงกดลงมาที่ถนน*

| รายการ | ค่า |
| :--- | :--- |
| แหล่งภาพ | คลิป CCTV มุมสูง 1444 x 1184 ที่ 27 fps |
| รับได้ | ไฟล์วิดีโอ, RTSP URL, เลขกล้อง webcam |
| เครื่องประมวลผล | MacBook ผ่าน PyTorch MPS |
| อัตราที่ประมวลผลจริง | ราว 13 fps จากการข้ามเฟรมเว้นหนึ่ง |
| ปลายทางที่ส่ง | `mqtt://127.0.0.1:1883` topic `traffic/6620301002` QoS 1 ทุก 10 วินาที |

```bash
.venv/bin/python main.py longvideo.mov          # ไฟล์
.venv/bin/python main.py rtsp://192.168.1.50/s  # กล้องสด
.venv/bin/python main.py 0                      # webcam
```

โค้ดเลือก device เอง ถ้ามี CUDA ใช้ CUDA ไม่มีก็ MPS ไม่มีอีกก็ CPU ย้ายไปรันบนเครื่องอื่นได้
โดยไม่ต้องแก้โค้ด ส่วนการข้ามเฟรมทำได้เพราะรถไม่ได้เปลี่ยนตำแหน่งมากใน 1/27 วินาที
ความเร็วที่วัดจึงไม่เพี้ยนแต่ภาระเครื่องลดครึ่งหนึ่ง

ตอนอ่านจากไฟล์และเปิดหน้าต่าง โปรแกรมหน่วงให้เล่นความเร็วปกติ ข้อมูลจึงห่างกัน 10 วินาทีจริง
ถ้าใส่ `--no-show` จะไม่หน่วง ข้อมูลถี่กว่านั้นและไม่เหมาะจะเอาไปเทรน

```python
info = mqtt_client.publish(MQTT_TOPIC, payload_str, qos=1)
if info.rc != mqtt.MQTT_ERR_SUCCESS:
    print(f"ส่ง MQTT ไม่สำเร็จ {MQTT_TOPIC} (rc={info.rc})", file=sys.stderr)
```

ต้องเช็ก `info.rc` ทุกครั้งเพราะ `publish()` ไม่โยน exception ตอนต่อ broker ไม่ได้
มันคืน rc = 4 เงียบ ๆ ข้อมูลจะหายโดยไม่มีคำเตือน
